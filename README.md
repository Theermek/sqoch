# Оформление билетов на мероприятие

SPA-сценарий покупки билетов на моковых данных: мероприятие → участники и контакт →
проверка заказа → результат (успех / места закончились / ошибка).

**Демо:** https://sqoch.vercel.app/ ·
сценарий «места закончились»: https://sqoch.vercel.app/?soldout=1

## Требования и запуск

Node 18+.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc + production-сборка
npm run preview  # просмотр собранной версии
```

## Как показать сценарий «места закончились»

Два равнозначных способа (общий переключатель в мок-API):

- **Demo-панель** в правом нижнем углу → режим «Места закончатся при подтверждении»;
- **query-параметр** `?soldout=1`, например `http://localhost:5173/?soldout=1`
  (на демо — https://sqoch.vercel.app/?soldout=1).

В этом режиме `confirmOrder` реджектится даже если на первом шаге места были — имитация того,
что билеты выкупили, пока пользователь заполнял форму. Остальные пути (успех, уменьшение
остатка мест) работают как обычно в режиме «Обычный».

## Структура

```
src/
  constants.ts              # цены и пороги возраста — одна точка правки
  types.ts
  domain/
    pricing.ts              # parseAge, getTicketType, getPrice, getTotal, формат цен
    validation.ts           # validateOrder -> { fieldErrors, formErrors, isValid }
    format.ts               # склонения «мест» / «билетов»
  api/mockApi.ts            # getEvent, confirmOrder, демо-режим sold out
  state/checkoutReducer.ts  # шаг, участники, email, статус запроса, результат
  components/
    EventCard.tsx  StepIndicator.tsx  ParticipantForm.tsx  ParticipantsStep.tsx
    OrderSummary.tsx  ReviewStep.tsx  ResultStep.tsx  DemoPanel.tsx
  App.tsx
  index.css
```

**Где бизнес-правила.** Только в `src/constants.ts` и `src/domain/` — чистые функции без React.
Поменять цену, порог детского билета (`CHILD_AGE`) или возраст сопровождающего (`ADULT_AGE`)
можно в одном месте, компоненты ничего не считают сами.

## Принятые решения

- **Тип билета вычисляется по возрасту** и не выбирается пользователем: `< 14` — детский,
  иначе полный.
- **15–17 лет — полный билет, но не сопровождающий.** Правило сопровождения требует участника
  `>= 18`, поэтому «ребёнок 10 + участник 15» остаётся ошибкой.
- **Возраст хранится в состоянии строкой** — это сырой ввод формы; разбор в `parseAge`.
  Иначе не отличить незаполненное поле от нуля и ломается ввод.
- **Один `useReducer` в `App.tsx`**, состояние и `dispatch` передаются пропсами. Для семи
  компонентов Context добавил бы слой без выгоды.
- **Защита от двойного клика на уровне редьюсера**: `CONFIRM_START` игнорируется при
  `status === 'loading'` (кнопка при этом тоже `disabled` и показывает «Оформляем…»).
- **Когда показывать ошибки**: поля — после попытки «Далее» (`showErrors`) или после `blur`
  поля (`touched`); правило сопровождения — блоком над списком. Валидация пересчитывается
  на каждый ввод, но не показывается до первого из этих событий.
- **Доступность**: `<label>` у каждого поля, `aria-invalid` / `aria-describedby` для ошибок,
  фокус на первое ошибочное поле после неуспешной отправки, `aria-live` на итоге и результате,
  тач-цели от 44px.
- Без роутера, Redux, UI-китов и бэкенда — по условиям задания.

## Незавершённые пункты / что улучшил бы

- Юнит-тесты на `domain/pricing.ts` и `domain/validation.ts` (Vitest) — самая очевидная
  следующая вещь: логика уже чистая и тестируется без React.
- Сообщения об ошибках сейчас заданы строками в `validation.ts`; при росте проекта их стоит
  вынести в словарь или в i18n.
- Мок-API не различает «места кончились между шагами» и сетевой сбой по ретраю: повтор в
  демо-режиме всегда даёт ту же ошибку.
